## Evaluation Protocol

### Cross-validation

- Pool: **4,301 chips** (reviewed pool minus benchmark)
- Split into **7 spatial bins** using 4×4 tile blocks, balanced by building count (two-pass: populated blocks first by building count, empty blocks by chip count)
- **5-fold CV**: fold k uses bin k as validation (~15%), bins 0–6 except k as training (~85%)
- Spatial binning prevents adjacent tiles from appearing in both train and val
- Generated by `scripts/make_cv_folds.py --val-frac 0.15`, output: `data/cv_folds/cv_folds.csv`

### Fixed benchmark test set

- **400 chips**, stratified by density band × region:
  - empty (0 buildings): 100 chips
  - sparse (1–9): 100 chips
  - moderate (10–49): 100 chips
  - dense (50–149): 100 chips
- Never used for training or threshold selection
- Scored via `scripts/benchmark_folds.py`; results in `data/review_charts/benchmark_folds.json`

### Primary metric: Panoptic Quality (PQ)

PQ = SQ × RQ where:
- SQ = mean mask IoU of matched pairs (mask quality)
- RQ = TP / (TP + 0.5·FP + 0.5·FN) (detection/separation quality)

**Empty chips are excluded from PQ** — chips with no GT buildings contribute nothing to the metric. FP rate on empty chips is now tracked separately (`fp_empty_chips`, `fp_empty_inst`) in `benchmark_folds.py` as of commit `e5f29513`. Old runs show `nan` for this field; it will populate when re-run.

### Why val PQ < test PQ

This is a composition artifact, not a generalisation gap:
- Val folds: 44–51% empty chips, median 5–7 buildings/chip on non-empty
- Benchmark: 25% empty, median 20 buildings/chip on non-empty
- Myanmar makes up ~70% of val folds vs 38% of benchmark
- Empty chips score PQ=0 and are already excluded, so the density difference is the main driver

Denser chips are **harder** for instance segmentation (touching walls, shared boundaries), so the benchmark is not easier. The gap is primarily from Myanmar-heavy val folds being sparser and harder to get consistent PQ on.

## Label Quality Classifier

### Goal

Score the remaining ~49k unreviewed chips to identify bad labels before the next training run. Bad = mask systematically wrong (shifted, missing buildings, wrong polygon).

### Reviewed chip statistics

- 6,459 chips with decisions
- keep ≈ 3,204 (68%), bad (needs_fix/drop) ≈ 1,488 (32%)
- Myanmar dominates (~61% of reviewed data), 29% bad rate there

### Approach 1: pred_feats XGBoost — AUC 0.8785

Script: `scripts/train_quality_classifier.py`  
Features: 9 hand-crafted features from model predictions (iou, prec, rec, gt_cov, pred_cov, boundary_grad, gt_comp_ratio, rgb_var_inside, pred_gt_comp_ratio)  
**Requires running the segmentation model on each chip first.**

### Approach 2: Frozen EfficientNet overlay — AUC 0.8387

Script: `scripts/train_overlay_classifier.py`  
Pipeline: composite GT mask as red overlay on RGB → frozen EfficientNet-B0 → 1280-dim GAP embedding → XGBoost  
**Only needs image + GT mask; no model inference required.**  
Lower AUC than pred_feats. Practical advantage: can score all 49k chips directly.

### Approach 3: Fine-tuned ResNet18 overlay — not yet run

Script: `scripts/train_label_encoder.py`  
Same overlay input, but ResNet18 is fine-tuned (not frozen) on the keep/bad classification task.  
Trains for 30 epochs; saves 512-dim penultimate embeddings for downstream XGBoost.  
Run: `python scripts/train_label_encoder.py --out label-cleanup/run2/label_encoder`

### Design rationale: why overlay not 4-channel input

ImageNet weights expect 3-channel RGB. A 4th mask channel would be randomly initialised and destabilise pretrained features. Instead: composite mask as semi-transparent red (alpha=0.5) onto RGB, keeping 3 channels and ImageNet priors intact.

### OOF threshold analysis (overlay, for reference)

| thr | accept | precision | recall | bad_caught |
|---|---|---|---|---|
| 0.90 | 2205 | 90.9% | 62.6% | 86.6% |
| 0.95 | 1818 | 93.3% | 52.9% | 91.8% |

At thr=0.90: ~86.6% of bad chips caught, 90.9% precision among accepted.

## Discussions / Decisions

- **Benchmark is fixed** — `nilsho01/vhr-buildings-benchmark-v1` (v1) is never modified; a potential v2 with 300 empty chips was discussed but deferred (not a scientific paper, time cost too high).
- **Empty chips in evaluation** — currently skipped for PQ; FP rate now tracked separately as `fp_empty_chips` (% of empty chips with ≥1 predicted instance). This is chip-level but accepted as practical for reporting.
- **Systematic label errors more dangerous than random noise** — shifted masks consistently push wrong gradients; random noise partially cancels. At >20% systematic noise the dist3 head is particularly sensitive.
- **Val PQ ≠ Test PQ by design** — composition difference is real and expected; do not interpret as generalisation failure.
